# Paper精读｜Skill1: Unified Evolution of Skill-Augmented Agents via Reinforcement Learning

> [!abstract] 一句话结论
> Skill1 把技能库 agent 的「选技能 → 用技能 → 蒸馏新技能」三个环节塞进同一个策略网络，让它们对着同一个任务结果信号协同演化——不另设任何辅助奖励。ALFWorld 和 WebShop 上<span class="mark-strong">超过了此前所有 skill-based 和纯 RL 方法</span>。

## 1️⃣ 论文想解决什么问题

现有技能库 agent 的生命周期包含三个耦合步骤：**技能选择**（从库中挑一个相关技能）、**技能使用**（在执行时用技能指导行为）、**技能蒸馏**（从轨迹中提炼新技能回写库中）。但现有方法的缺陷是：

1. **优化不完整**——每个方法只优化生命周期的一个子集，比如只优化利用和蒸馏、不管选择，导致选择卡脖子；

2. **奖励来源分裂**——不同阶段用不同的奖励信号（有的用任务结果，有的用自评质量或启发式匹配分数），导致各阶段朝不同方向优化，互相冲突。

Skill1 的核心问题是：**如何让三个技能生命周期协同演化，所有信号都来自同一个任务奖励？**

---

## 2️⃣ 核心洞察

> [!ed-quote] 核心洞察
> **"<span class="mark-strong">低频趋势 + 高频波动</span>" 的单一信号分解**。

Skill1 的关键洞察是：单个任务结果信号 `r(τ)` 本身就包含不同时间尺度的信息——在训练过程中，多个 rollouts 之间：

- **低频趋势**（多个 rollouts 的平均奖励）反映的是「选对了技能没有」——如果某个技能被选中时平均奖励高，说明选择做得好；

- **高频波动**（单个 rollout 偏离均值的差异）反映的是「当前 rollout 的质量」——某条 rollout 远好于平均，说明这趟行为值得蒸馏成技能。

这样，一个信号既能同时给「选择」和「蒸馏」两个阶段提供针对性梯度，<span class="mark-strong">不需要额外设计内在奖励</span>。

---

## 3️⃣ 方法解读

### 整体流程

对于一个任务 `x`，策略 `π_θ` 按顺序执行三个阶段，完成一条完整轨迹 `τ = (q, z, a₁, o₁, ..., a_T, o_T, s_new)`：

```
任务 x → 生成查询 q → 检索 top-K 候选 → 重新排序选出 z → 在 z 指导下交互 → 反思蒸馏出新技能 s_new
    ↑________ 选择阶段 _______↑      ↑____ 使用阶段 ____↑     ↑____ 蒸馏阶段 ____↑
```

### 阶段一：技能选择

1. 策略生成自然语言查询 `q` → 用冻结的编码器 `ℰ`（all-MiniLM-L6-v2）检索语义相似度最高的 top-K 候选

2. 策略对 top-K 候选**重新排序**，选出排名最高的技能 `z`

3. 注意：查询生成和重排序都由 `π_θ` 完成 → 选择阶段可以直接通过策略梯度优化

### 阶段二：技能使用

策略基于选中的技能策略描述 `z.strat`，与环境交互最多 T 轮。对于每个任务，采样 G=16 条独立 rollout，每条 rollout 独立完成自己的选择、使用和蒸馏。

### 阶段三：技能蒸馏

任务完成后，策略反思整条轨迹，生成：

- 可复用策略 `s_new.strat`：描述"怎么做"

- 适用场景描述 `s_new.desc`：描述"什么时候用"

只有当 `r(τ)=1`（任务成功）时才将新技能加入库。库容量限制 |ℬ|≤5000，淘汰策略：优先移除「低效用 × 低频次」的技能。

### 联合优化目标

Skill1 没有另起炉灶，优化直接架在 GRPO 上改：

对于每个任务 d，采样 G 条 rollout `{τ_i}`。每条 rollout 的 group-relative advantage 为：

```
Â_i = (r(τ_i) - mean(r)) / std(r)
```

**关键分解**：同一个优势 `Â_i` 拆成两路，各喂一个阶段：

- **选择阶段**：使用**低频趋势信号**（多个 rollout 的平均奖励）来更新选择策略 → `ℒ_select = Â_trend · log π_θ(z|x)`

- **蒸馏阶段**：使用**高频波动信号**（单个 rollout 偏离均值）来更新蒸馏策略 → `ℒ_distill = Â_variation · log π_θ(s_new|τ_i)`

- **利用阶段**：直接使用完整优势 → 标准 GRPO 更新

三个目标的权重通过 `λ₁` 和 `λ₂`（均为 0.3）调节。

## 理论贡献 / 机制解释

1. **单一信号的频率分解**：首次把同一个任务结果信号按频率拆开，分别指导选择和蒸馏的梯度更新——不造新奖励，两个阶段各要的东西本来就在同一条轨迹里。

2. **三阶段全链路可微**：查询生成和重排序都由 `π_θ` 完成，使得选择的每个子步骤都暴露在策略梯度下。

3. **生命周期的闭环**：选择 → 使用 → 蒸馏 → 入库 → 后续任务再选择，形成一个完整的闭环演化，三个环节相互增益。

## 4️⃣ 实验部分怎么读

### 实验设置

| **维度** | **值** |
| --- | --- |
| 环境 | ALFWorld（文本家务，6 个子任务类型）、WebShop（商品搜索购买） |
| 基础模型 | Qwen2.5-7B-Instruct |
| 编码器 | all-MiniLM-L6-v2（冻结） |
| 训练算法 | GRPO，G=16，lr=1e-6 |
| 计算资源 | 8 × H800-80GB |
| 库容量 | ≤5000，初始为空 |
| 训练收敛 | ~100-150 steps（ALFWorld 约 30 小时） |

### 主要结果

| **方法** | **ALFWorld (avg)** | **WebShop (avg)** |
| --- | --- | --- |
| Skill1 (Ours) | **97.5** | **83.2** |
| RetroAgent | 94.9 | 78.5 |
| GiGPO (最佳纯RL) | 91.0 | — |
| SkillRL | 89.8 | 75.4 |

Skill1 在 ALFWorld 的<span class="mark-number">6 个任务类型中 5 个达到最优</span>，比第二好的 RetroAgent 高 2.6 个百分点。

### 消融实验关键发现

移除三个信号分解中的任何一个都导致性能下降：

- **移除趋势信号**（选择无梯度）：选择退化为随机检索，利用率下降 → 选不对技能

- **移除波动信号**（蒸馏无梯度）：蒸馏质量下降 → 新技能质量差、利用率下降

- 选择、利用、蒸馏三者互相耦合，<span class="mark-strong">去掉任何一个信号都会影响其他环节的演化</span>

### 统计显著性

Skill1 vs RetroAgent：Welch's t-test p=0.021 (<0.05)，3 个随机种子方差更小（0.6 vs 0.9）。

## 5️⃣ 学术评价

**亮点**：

- 单一任务信号驱动三阶段演化，哪个环节都不用单独造奖励，工程上是真的省事

- 频率分解的直觉漂亮——对应到控制论中的 set point tracking vs. disturbance rejection

- 实验完整，包含统计显著性检验

- 代码开源

> [!ed-warning] 可以改进的点
> - 只评测了文本环境（ALFWorld、WebShop），视觉环境未覆盖
>
> - 7B 规模模型，更大模型（70B+）的行为未见分析
>
> - 库容量 5000 的上限如何影响长尾任务性能未充分讨论
>
> - 编码器固定（all-MiniLM-L6-v2），是否可以通过 end-to-end 学习查询/库编码来进一步提升？

---

## 6️⃣ 局限与可扩展方向

1. **环境覆盖不足**：仅两个文本环境，扩展到搜索引擎或视觉环境尚未验证

2. **技能库扩展性**：5000 条硬上限，更复杂场景可能需要层级化组织或动态容量

3. **技能语义漂移**：随蒸馏不断加入新技能，早期技能的语义是否会被覆盖、造成灾难性遗忘？

4. **单一 base model**：Qwen2.5-7B，更大模型和不同系列未验证

5. **安全风险**：自蒸馏的技能库可能编码有害行为序列，需要 human-in-the-loop

---

## 7️⃣ 最后总结

这篇的贡献不在发明新 RL 算法，而在**从控制论视角重新理解了技能生命周期的耦合关系**——<span class="mark-strong">用一个信号、三个频率分量</span>，让选择/使用/蒸馏三个环节协同演化，消融也证实了耦合是真的：去掉任何一个分量，其他环节跟着退化。这种"统一信号、分解使用"的思路，比此前各管各的辅助奖励设计干净得多；后面再做 skill-based agent 的对比实验，这篇大概率绕不开。

## 8️⃣ 三句速记

> [!summary]- 点开展开
> 1. **单一信号频率分解**：将任务结果信号按低频趋势（指导选择）和高频波动（指导蒸馏）分解，无需辅助奖励
>
> 2. **全链路可微**：从查询生成到重排序全由 `π_θ` 输出，暴露在选择梯度下
>
> 3. **三环节闭环演化**：选→用→蒸馏→入库→再选，实验证明移除任何信号都导致退化
